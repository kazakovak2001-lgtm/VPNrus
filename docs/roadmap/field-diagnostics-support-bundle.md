## Notes

Automatic, sanitized, structured connection diagnostics for remote support - no developer mode/ADB/logcat required from the tester. **Model**: `DiagnosticSession` (session id, app version, coarse network facts, `rawRestrictionClass`/`stabilizedRestrictionClass`, routing/gateway-selection mode, `selectedPathKind` - `DIRECT`/`CHAIN_DIRECT`/`CHAIN_CDN`/`PRIVATE`/`NONE`, selected transport, a bounded `events` timeline capped at 200, outcome, failure reason) - no endpoint host/IP, only enum labels and the existing coarse `NetworkFingerprinter` id. `DiagnosticEventType` (19 categories) is a labeling vocabulary over this codebase's own real state (`RestrictionClassifier`/`RestrictionStabilizer`, `AutoGatewaySelector`, `VpnSessionHealth`, `RelayReadinessStage`, `IngressActivationOutcome`) - never a second connection state machine. `DiagnosticFailureReason` (17 categories) is populated by pure mapping functions from the existing `VpnError`/`RelayFailureCategory`/`IngressActivationOutcome`/`RestrictionClass` types, never replacing them. **Automatic capture**: `SupportDiagnosticsRecorder` is the one place a session is assembled - narrow, typed `record*`/`finish*` functions (every `record*` function has zero raw `String` parameters, no exception, reflection-proven; PR #43 review fix removed a one-method exception for `recordManifestSourceSelected`, which now takes the closed `ManifestSourceKind` enum instead of a free-text label); non-terminal `record*` calls append to a still-open session (a multi-candidate Auto failover sequence stays ONE session/timeline), terminal `finish*` calls close it (idempotent - a generic backstop and a precise typed call can never double-record). Wired into `MainViewModel` as an additive nullable constructor param at `connectAuto`/`connectManual`/`connectPrivate`/`attemptCombined`/`attemptRelayedAttempt`/`armFailoverWatch`, plus a generic `sessionHealth`-StateFlow collector backstop that guarantees no session is ever left open forever. `InMemoryDiagnosticSessionStore` bounds retention to the last 8 sessions, oldest-first eviction - no unlimited logging. **Snapshot consistency**: `connectAuto`'s raw/stabilized restriction fields come from the SAME `CombinedAutoRankingSnapshot` (B28) that decided the ranked attempts, never independently recomputed. **Sanitization**: two layers - structural (the recorder's API cannot accept a raw string at all) plus a pattern-based defense-in-depth pass (`DiagnosticSanitizer`) applied a second time at export, rejecting UUID-shaped strings, long mixed-case Base64 key-shaped blobs, bearer auth headers, PEM blocks, credential key-value pairs, URLs with query data, and IPv4/IPv6 addresses - replaced with a fixed `[redacted]` marker, never a partial echo. Proven with deliberately-planted secret sentinel strings (UUID credential, real-shaped AWG key, bearer token, PEM block, URL with secret query param, endpoint IP) confirmed absent from the exported JSON. **Bundle/export/UI**: `buildSupportBundle`/`toJson()` (deterministic, fixed key order); `MainViewModel.exportSupportBundleJson()`/`recentDiagnosticSessions()`/`clearDiagnosticSessions()`/`lastConnectionResultSummary()`; `SettingsScreen`'s new "Diagnostics" section shows only a simple human-readable last-result sentence with "Export diagnostics"/"Clear diagnostics" one tap away; export triggers a real Android `ACTION_SEND` share-sheet intent - never an automatic/silent upload to any backend (no telemetry service exists or was added this slice). **Tests**: `DiagnosticSanitizerTest`, `DiagnosticSessionStoreTest`, `SupportDiagnosticsRecorderTest` (DIRECT/CHAIN_DIRECT/CHAIN_CDN success, RestrictedNetworkNoViableRelay, transport/data-plane/relay-proof/activation/control-plane failures, raw-vs-stabilized consistency, last-attempt-wins recording, bounded events, abandon-on-supersede), `SupportBundleTest`, `DiagnosticTypesTest`, and `MainViewModelSupportDiagnosticsTest` (a real successful manual connect end to end; the exported bundle never leaks a real gateway config's own host/public key/tunnel IP). All new tests plus the full existing suite green (1148 total), `compileDebugKotlin`/`assembleDebug` green. **Not done this slice**: no field-testing with a real user/support workflow (stays FOUNDATION-only until that happens); no backend telemetry/upload endpoint exists or was added (export is local share-sheet only); not every single MainViewModel failure branch carries an individually-instrumented precise typed reason (the generic sessionHealth backstop covers the remainder); no persistent (disk-backed) session store yet - sessions do not survive app process death.
