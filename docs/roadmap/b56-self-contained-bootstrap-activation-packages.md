## Column 3

Design proposal for a signed, portable activation package that lets a new install verify and attempt activation before the primary control-plane API is confirmed reachable. Corrected design splits the package into two independently authenticated objects - an `ActivationEnvelope` (new delegated activation-issuer key, entitlement only, never a network fact) and an optional `SignedBootstrapBundle` (the EXISTING manifest signing key, offered through the existing unmodified `EndpointManifestRepository.offer()`) - so an out-of-band package can actually recover a device whose known endpoints are all blocked, not merely reorder them. Defines a two-level bootstrap reachability model (Level 1: direct control-plane over existing reachability infra; Level 2: architecture-only restricted pre-activation transport, not built), with two explicit package modes - a Standard Activation Package (Level 1 only) and a Level-2-Capable Recovery Package, which always carries its bootstrap capability PRE-ISSUED so entering the restricted lane never depends on reaching a live issuance endpoint first (live issuance is an optional optimization only, never a hard prerequisite). Full audit, trust model, package format, rollback precedence, threat model, and slice breakdown in [`RESILIENT_BOOTSTRAP_ACTIVATION_ARCHITECTURE.md`](RESILIENT_BOOTSTRAP_ACTIVATION_ARCHITECTURE.md). Verdict: architecture ready with explicit owner decisions (milestone number, rate-limiting priority, self-service issuance timing, Level 2 rollout timing) - see that document's Decision Gate. No whitelist/Russia-bypass claim made; the repo vhost configs for `/v1/activate` and `/v1/manifest` now carry Level 1 nginx edge rate/concurrency limiting (not deployed) - see B56-3 below (this was the confirmed gap at the time this row was first written). **B56-1 IMPLEMENTED**: `ActivationEnvelope`/`SignedActivationEnvelope` schema, deterministic canonical encoding with domain separation (`net.pocvpn.client.activation.ActivationEnvelopeCanonicalizer`), strict bounded parser/wire codec (`ActivationEnvelopeCodec`), Base64URL text transport (`ActivationEnvelopeTextCodec`), a dedicated activation-issuer trust-anchor type disjoint from manifest trust anchors (`ActivationIssuerTrustAnchors`/`FixedActivationIssuerTrustAnchors`), and an Ed25519 verifier with typed failures and a single clock-skew policy reused from `Ed25519ManifestVerifier` (`Ed25519ActivationEnvelopeVerifier`) - pure Kotlin/JVM, no Android framework dependency, no network/UI code, no production activation-issuer key. Both routes additionally share one 20-connection-per-IP concurrency zone (`pocvpn_bootstrap_conn`) - this, not either `burst` value, is the actual concurrent-request ceiling per source IP: `burst=60` never means 60 simultaneous manifest requests can be in flight at once from one IP; at most 20 of any combination of activate+manifest requests from that IP are ever processed concurrently. The request-rate burst allowances absorb short legitimate shared-CGNAT bursts, while the separate shared 20-connection-per-source-IP ceiling bounds concurrent processing - this is an explicit abuse-damping TRADE-OFF, not a guarantee: a legitimate client behind an unusually large or bursty CGNAT population sharing one public IP CAN still receive `429` once these bounds are exceeded. **This is Level 1 application-edge abuse damping only - explicitly NOT volumetric/network DDoS protection, NOT a censorship or hard-whitelist bypass, and independent of B56-2's imported-manifest path** (see `RESILIENT_BOOTSTRAP_ACTIVATION_ARCHITECTURE.md` section 22's "four independent layers" - this is layer 1 only; Level 2's own capability-scoped limits remain a separate, later slice).
