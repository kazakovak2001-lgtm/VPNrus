A path shape with no trusted origin contributes no candidate at all - never an empty-origin placeholder), and `ActivationPathOriginSetBuilder` (flattens those candidates into the SAME `List<ControlPlaneOrigin>` shape `ActivationResilienceCoordinator.activate`'s existing `origins` parameter already accepted pre-B67.2 - the ONE integration seam, `MainViewModel`'s existing `controlPlaneOriginsForActivation` constructor seam, repointed from `ControlPlaneOriginSetBuilder::forGateway` to `ActivationPathOriginSetBuilder::forGateway`). No second scorer, no second retry/bounded-execution engine, no second manifest/trust/endpoint model, no second provisioning system: `TrustedOriginRequestExecutor` (B30, completely unmodified) already gives the concatenated multi-path origin list exactly the required semantics - each origin across every path shape attempted at most once in fixed order, `AUTHORIZATION_REJECTED` on ANY origin/path terminal for the whole call (B30 invariant preserved unchanged), a network/connectivity-type failure on one path shape's origin(s) falling through to the next shape in the same bounded loop, never a recursive/second loop. `ActivationResilienceCoordinator`/`MainViewModel.activateDevice()`'s success/persistence/provisioning logic are byte-for-byte unmodified. **PRODUCTION PATH AVAILABILITY, stated plainly: DIRECT = available (unchanged); CHAIN_DIRECT = NOT deployed, `TrustedChainControlPlaneOriginCatalog.chainDirect` returns `emptyList()`; CHAIN_CDN = NOT deployed, `chainCdn` returns `emptyList()`** - the one deployed B25/B31 Stockholm ingress relays DATA-PLANE VLESS traffic, not HTTPS control-plane calls, and is never reused as a control-plane front - so `ActivationPathOriginSetBuilder.forGateway` is currently byte-for-byte the same single-DIRECT-origin list `ControlPlaneOriginSetBuilder.forGateway` alone always produced; existing single-path production activation behavior is unchanged, and real production activation remains DIRECT-only today, not yet a genuine three-path system. 15 deterministic unit tests (`ActivationPathCandidateTest`, synthetic trusted origins via the internal test seam, no live network) prove the composition/fallback MECHANISM -
