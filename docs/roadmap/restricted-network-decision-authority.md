## Notes

Makes real `RestrictionClass` evidence (B18/B23) decision-driving for automatic DIRECT vs RELAY path ranking for the first time, reusing the existing candidate/scoring fabric - no second decision authority, no country/provider hardcoding, no deployment or physical device dependency. **The exact rule**: `PathScorer.score` (`reachability/PathScorer.kt`) gains one new tier, `RESTRICTION_TIER = 700` (sandwiched strictly between `HISTORY_TIER=1000` and `MATURITY_TIER=200`, tier-algebra re-verified for all five tiers in the class doc). Nonzero ONLY for `RestrictionClass.POSSIBLE_HARD_WHITELIST`: `+1` for `PathCandidate.Relayed`, `-1` for `PathCandidate.Direct`, `0` for every other class (NORMAL/UNKNOWN never forces relay). The bonus depends only on candidate TYPE, never `IngressKind` - `DIRECT_IP` and `CDN_FRONTED` relayed candidates get the identical bonus, so neither ingress kind is globally preferred; their own reachability/health/history still decides ranking between them. `POSSIBLE_UDP_OR_AWG_FILTERING` gets no dedicated branch - it is itself derived from a real `awgHandshakeFresh == false` `ConnectionOutcome`, which already penalizes `AMNEZIA_WG` via the pre-existing `HEALTH_TIER` (`TransportHealthCalculator`), so a second protocol-specific branch would be redundant nested if/else. `PathScorer.isEligible`/`ineligibilityReason` gained zero new logic - restriction only affects score among already-eligible candidates, so an ineligible relay (fresh UNREACHABLE, no valid profile) can never be promoted by the bonus; when hard-whitelist evidence is suspected and no eligible relay exists, `buildCombinedAttempts` yields no `RelayedAttempt` at all and a genuinely reachable Direct path is still offered truthfully - never fabricated, never suppressed. Evidence stays distinct: endpoint reachability, transport health, real end-to-end proof (B25/B26), and restriction classification remain four separate fields feeding four separate `PathScorer` tiers, never collapsed into one boolean. **Hysteresis (TTL, explicit and time-bound)**: `RestrictionMonitor` now stamps `lastProbeEpochMillis`/`lastDiverseReachabilityEpochMillis` (real wall clock via an injectable `nowProvider`, still triggered only by a real transport-state/network-type transition, never a timer); `RestrictionEvidence` gained matching optional `gatewayProbeEpochMillis`/`diverseProbeEpochMillis` fields; `RestrictionClassifier.classify` gained `nowEpochMillis`/`staleAfterMillis` params (default 30 minutes, the same window `ReachabilityEngine` already uses) - once a probe's own timestamp is stale (or future-dated), its value is treated as unknown rather than trusted indefinitely, decaying `POSSIBLE_HARD_WHITELIST`/`POSSIBLE_UDP_OR_AWG_FILTERING` back toward `UNKNOWN`. Backward compatible: an undated value (every pre-B28 caller) is legacy-trusted as-is, so no existing classification changed. **Diagnostics**: `MainViewModel.combinedAutoRankingDiagnostics()` (new) maps the already-public, already-ranked `combinedAutoAttempts()` output into `{restrictionClass, ranked: [{kind: "DIRECT"
