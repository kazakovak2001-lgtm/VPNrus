## Pipeline conclusions

- `VlessXhttpTransport` receives only opaque Xray lifecycle events. It does not receive DNS phase, TLS phase, HTTP status, CDN edge, CDN-to-origin, or proxy-stage results.
- `XrayCoreRuntime.measureDelay` returns a delay or throws. `XrayCoreController` intentionally converts every thrown/expired native confirmation into the coarse typed fact `REMOTE_UNCONFIRMED`; it does not inspect the throwable message.
- `HttpRelayEndToEndProbe` is a separate, VPN-excluded HTTPS proof channel. Its exact exception subtypes can describe that request only. Its numeric non-200 status proves proof failure, but the current contract does not make 405, 429, 500, 502, or 503 authoritative XHTTP/CDN/origin facts.
- `NotProvisioned` is a relay preparation result, permission denial is a pre-connect error, and neither is a transport-network failure.
- `AutoGatewayFailoverPolicy` remains the only retry eligibility authority. Diagnostic mapping functions are pure and their output is never supplied to that policy.

No B36/B37 failure was physically observed in the 2026-09-14 checkpoint. Physical coverage remains absent by design for R3; any later validation must use a safe non-production fault harness.
